# Desktop bridge

The native process owns a single vault session and the only filesystem access. The renderer may invoke `vault_open` (native folder picker), `vault_list`, `vault_read`, `vault_stat`, and `vault_write`. Their values use the existing Electron envelopes (`{ok:true,...}` or `{ok:false,error:{code,message,path,reason}}`); cancelling the picker returns `{ok:false,canceled:true}`. Reads and writes use a vault-relative `path`; `vault_write` additionally requires `content` and `expectedVersion`. A string performs a checked save and explicit `null` requests a confirmed unchecked overwrite. Omission is rejected, never interpreted as an overwrite. `vault_stat` returns `{ok:true,note:null}` only when the note has been removed.

The frontend installs its close listener before enabling vault access. Native close requests are blocked by default; the listener checks dirty/saving state and uses an in-document asynchronous confirmation before destroying the window. The frontend does not report clean state via `set_dirty`, so the native guard remains fail-closed. The `core:window:allow-destroy` capability permits the listener to finish a clean or confirmed close. Linux window-manager close was exercised with a temporary fixture; crashes and forced termination cannot preserve unsaved drafts.

No filesystem, shell, or frontend dialog plugin permission is granted. Folder selection happens in native Rust; close confirmation is provided by the frontend's webview dialog. The CSP allows only bundled assets and Tauri IPC. Run `cargo tauri dev` with Tauri CLI installed, or build the frontend then `cargo run --release --features custom-protocol --manifest-path src-tauri/Cargo.toml`; Linux requires the Tauri system dependencies (GTK 3, WebKitGTK 4.1, pkg-config, and a C toolchain). Bundling is disabled until application icons/package metadata are supplied.
